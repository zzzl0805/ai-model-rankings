# AI模型排行 — 修正与优化方案

围绕两条生命线：**数据准确性** + **用户体验**

---

## 一、数据问题（生命线）

### 问题清单

| # | 问题 | 严重度 | 现状 |
|---|------|--------|------|
| D1 | 46%模型无定价 | 🔴高 | 175/378 无价（ERNIE/Kimi/Qwen/Mimo/混元/豆包等） |
| D2 | 定价来源不统一 | 🔴高 | GLM用官网，其他用OpenRouter代理价（差±67%） |
| D3 | 模型名是英文ID | 🟡中 | 显示 "claude-opus-4-6-thinking"，不友好 |
| D4 | 缺厂商中文名 | 🟡中 | provider 字段为空或英文 |
| D5 | 无数据更新时间标注 | 🟡中 | 用户不知道数据新旧 |
| D6 | 无置信度提示 | 🟡中 | 票数少的模型分数不可靠，但没提示 |

### 修复方案

**D1+D2：定价数据补全（最重要）**

建立分厂商的官方价数据库：
```
data/prices/
├── zhipu.py        # 智谱（已做）
├── moonshot.py     # Kimi（待做）
├── alibaba.py      # 通义千问（待做）
├── baidu.py        # 文心（待做）
├── bytedance.py    # 豆包（待做）
├── tencent.py      # 混元（待做）
├── xiaomi.py       # Mimo（待做）
├── minimax.py      # MiniMax（待做）
├── anthropic.py    # Claude官方价（待做）
├── openai.py       # GPT官方价（待做）
└── google.py       # Gemini官方价（待做）
```

优先级：官方价 > OpenRouter代理价，明确标注来源。

**D3+D4：模型名映射表**

建立 `model_names.js`：
```javascript
{
  "claude-opus-4-6-thinking": {
    "displayName": "Claude Opus 4.6",
    "providerCN": "Anthropic",
    "providerLogo": "🅰️",
    "variant": "思考模式"
  },
  "glm-5.2": {
    "displayName": "GLM-5.2",
    "providerCN": "智谱AI",
    "providerLogo": "🔵"
  }
}
```

**D5+D6：元数据**

每个模型增加：
```javascript
{
  "lastUpdated": "2026-07-24",
  "confidence": "high",  // high(>5000票)/medium(>1000)/low(<1000)
  "priceSource": "智谱官网"  // 明确来源
}
```

## 四、数据准确性保障

### 数据校验机制
```
每次更新数据后自动校验：
1. 重新爬取LMArena前10，对比存储数据（已有脚本）
2. 抽查定价 vs 官网
3. 检查模型名是否清理干净
4. 输出校验报告
```

### 数据更新流程
```
1. node scrape_lmarena.js     # 爬排行
2. node scrape_agent.js       # 爬Agent
3. python3 build_rankings.py  # 合并+定价
4. node verify_scores.js      # 校验
5. 人工抽查 → 发布
```

### 来源透明
每个数据点都带 `source` 字段，详情页可见，让用户知道数据出处。
