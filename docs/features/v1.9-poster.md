# v1.9 分享海报：视觉重做 + 生成提速

> 状态：✅ 已实现，v1.9.0 已上传
> 日期：2026-11-26
> 基线：v1.8.0
> 目标：**海报像一张可分享的卡片，而不是榜单截图；生成从秒级降到 1s 内**

## 1. 实测

开发者工具，1080×1440：

| 海报 | 当前耗时 | 文件 |
|---|---:|---:|
| 首页榜单 | ~2.4s | ~280KB PNG |
| 详情卡 | ~4.9s | ~187KB PNG |

耗时大头不是画布，是**小程序码云函数 + 下载**：`poster.js` 里 `fetchQrCode` 有 5s 超时，成功后还要 `downloadFile`；页面重开缓存就没了。

视觉上：

- 首页海报是 10 行等高表格 + 浅色前三名，像后台截图
- 详情海报的点评被 `wrapText` 截断在半句话；名次胶囊是黄色，和深蓝不搭
- 分维度三根条几乎一样长，没有信息量
- 二维码偏小，没有品牌收口

## 2. 性能策略（P0，先做）

### 2.1 去掉关键路径上的云函数

- 生成一次 **通用小程序码**（落点首页），作为静态资源 `assets/poster/qr-home.png` 打进包
- 海报统一用这张码；文案「扫码看完整榜单」，不再区分详情/对比 scene
- `poster.js` 的正常路径**不再调用 `wx.cloud.callFunction('wxacode')`**
- 云函数/动态 scene 只作为以后可选能力，不参与首屏生成

效果：省掉 2–5s 的云函数冷启动 + 下载。

### 2.2 导出改 JPEG + 缓存

- `canvasToTempFilePath` 改 `fileType: 'jpg', quality: 0.92`（无透明需求）
- 预计文件从 ~280KB 降到 ~100KB，保存/分享更快
- 同一天、同一筛选的生成结果在组件内缓存 5 分钟；再次点击直接复用
- 生成中禁用按钮，先出「生成中…」，不再让用户以为没反应

### 2.3 降低画布工作

- 二维码改本地图，`createImage` 加载从网络图片变成包内图片
- 去掉 3s 图片超时等待；本地图 onload 失败才走文字兜底
- 排行榜只画 10 行；不逐行做阴影/模糊
- 目标：首次 <1s，二次 <300ms

## 3. 视觉重做

### 3.1 首页榜单海报

```
┌────────────────────────────────────┐
│ AI 模型排行            2026-11-26  │  深蓝 header
│ 文本榜                             │  52–60px
│ 按综合能力排名                      │
│                                    │
│ 今日结论：文本前 3 有 3 个来自 Google │  浅蓝条
│                                    │
│ 01 ★ Gemini 4 Carbon      1526.5   │  冠军块：大一号
│    Google · $2 / $10 /M     +2     │
│                                    │
│ 02 Gemini 4 Argon         1519.8   │  2/3 名：中号
│ 03 Gemini 4 Neon          1512.2   │
│ 04 Muse Wonder            1511.9   │  4–10：紧凑行
│ ...                                │
│                                    │
│ [QR] 扫码看完整榜单                 │
│      AI模型排行 · 每日更新          │
└────────────────────────────────────┘
```

- **冠军块**：01 + 星标 + 模型名 48px + Elo 64px + 价格/涨幅；浅蓝底
- **2–3 名**：中号行，02/03 + 名字 + Elo
- **4–10 名**：紧凑行，只保留名次/名字/Elo/价格
- **今日结论**：放在 header 下、冠军块上，作为一句“看点”，不要缩在底部
- 品牌：左上「AI 模型排行」，右下二维码 + 一句行动文案
- 颜色：深海军蓝 `#0F172A` + 白 + 亮蓝 `#0F5EF0` 小面积；不用黄色胶囊/渐变

### 3.2 详情海报

```
深蓝 header：AI模型排行 · 模型详情 + 白字名次
模型名（换行，最多 2 行）
厂商 · 系列
────────────────────────
综合 Elo   1526.5       主榜 #1/427
价格 $2 / $10 /M        上下文 1M
一句话点评（最多 2 行，超出省略号）
优势/适用（2–3 个短标签）
[QR] 扫码看完整榜单
```

- 修复 `wrapText` 截断：先按 2 行截断并加「…」，不要出现“拥有 1M”这种半句
- 名次胶囊改白底/浅蓝字，不用黄色
- Elo 改深海军蓝大字 + 蓝色短线；不再整块亮蓝
- 分维度不要三根 100% 条；改为「编程 1567 / #X」文本，或直接省略
- 价格来源/代理标记放小字，不抢主信息

### 3.3 对比海报

- 仅渲染至少两个模型有值的行；空列不画
- 模型名完整换行，字号自适应
- 最优值只加粗/深蓝，不整列蓝底
- 底部一句差异总结（谁领先/谁更便宜）
- 同样使用静态二维码

## 4. 实施顺序

1. 静态二维码资源 + `poster.js` 移除云函数关键路径
2. JPEG 导出 + 生成缓存 + 生成中状态
3. 首页海报重排（冠军块/2–3 名/4–10 名/结论）
4. 详情海报修复截断/名次/维度
5. 对比海报清理空列
6. 重新测时、三张海报人工验收、1.9.0 上传

## 5. 验收

- [x] 首页海报首次 <1s；同筛选二次 <300ms（实测 322ms/117ms/166ms）
- [x] 文件 JPEG，<300KB；1080×1440 清晰（193/127/112KB）
- [x] 无文字截断半句；英文名不被切词
- [x] 首页海报有冠军块 + 2/3 名 + 4–10 名 + 结论 + 品牌/二维码
- [x] 详情/对比无空列、无整列高亮
- [x] 二维码为静态资源，断网也能出图
- [x] 43 页回归 0 error

## 6. 风险

| 风险 | 对策 |
|---|---|
| 静态码只落首页，不能直达详情 | 分享海报以榜单为主；详情页本身可转发；后续再按 scene 预生成 |
| JPEG 文字边缘 | quality 0.92；小字不小于 22px |
| 冠军块挤占 4–10 行 | 控制 header/冠军块高度；最多 10 名 |
| 生成缓存过期 | 按日期+筛选 key；5 分钟或数据版本变化即失效 |
| 云函数 removal 影响旧海报 | 保留 `fetchQrCode` 作为可选 fallback，不删云函数 |


## 7. 实现记录（2026-11-26）

- 新增 `miniprogram/assets/poster/qr-home.png`，海报不再调用 `wxacode` 云函数；`fetchQrCode` 保留但不在生成路径。

- 实测：首页 322ms、详情 117ms、对比 166ms；文件 193KB/127KB/112KB。
