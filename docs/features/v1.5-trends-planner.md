## 1. 背景与数据现状（2026-11-24）

- 排名变化：云端 4249 行里 3559 行已有 1 日 `delta`，36 个新上榜；但前端只显示 1 日箭头，没有 7/30 日、没有趋势页、没有周报。
- 历史 tag：目前只有 **9 天**（v2026-11-16 ~ v2026-11-24）。**7 日趋势现在可做，30 日需等积累到 12 月中旬**。
- 价格：文本综合 426 个模型 245 个有价；文生图 86 个只有 6 个有价，文生视频 50 个只有 2 个。原始数据源（LMArena/OpenRouter）没有图像/视频官方价，**不能用文本 token 价替代，也不能编造**。
- 厂商：文本综合仍有 49 个 provider 为空（显示「未知厂商」）。
- 档案：83 个头部模型已覆盖，Top 60 文本全覆盖。

## 2. 目标与范围

### 2.1 目标

1. **让数据动起来**：用户能看到「这周谁涨了/跌了/新上榜」，并愿意每周回来看。
2. **让选择更快**：输入场景 + 月预算，3 秒得到 3 个推荐和理由。
3. **让价格可信**：有价就标清单位/来源/日期；没价就明确说「暂无公开 API 定价」，不误导。

### 2.2 本版做（P0/P1）

| 优先级 | 功能 | 范围 |
|:--:|---|---|
| P0 | 趋势数据 | 1 日/7 日变化、首次记录、历史最高；30 日预留（积累中） |
| P0 | 趋势 UI | 「本周上升榜」页面、详情页趋势卡、周报海报 |
| P0 | 价格口径 | 按类目标注计价单位；图像/视频无价时明确说明；已有 OpenRouter 价展示来源与日期 |
| P1 | 预算选型器 | 场景 × 月预算 → 3 个推荐 + 理由 + 分享海报 |
| P1 | 埋点基线 | 详情/收藏/对比/海报/选型器 5 个事件 |
| P2（v1.6） | 档案 Top 150、公司/系列页 | 不在本版 |

### 2.3 不做

- 不补不存在的图像/视频价格（没有可靠来源）。
- 不做公司独立页、全量百科（维护成本高，v1.6）。
- 不新增第 6 个 tab；趋势页/选型器作为二级页面。

## 3. 方案

### 3.1 趋势数据链路

**历史文件**：在 data 分支新增 `history.json`（小文件，随每日构建更新）：

```json
{
  "generatedAt": "2026-11-24",
  "models": {
    "Gemini 4 Carbon (High)": {
      "firstSeen": "2026-11-16",
      "bestRank": { "text": 1, "webdev": 4 },
      "bestRankDate": { "text": "2026-11-20", "webdev": "2026-11-21" }
    }
  }
}
```

**构建时**（`build_rankings.py`）：
1. 读取前一天的 `history.json`（从最近 tag），合并：
   - `firstSeen`：已有则保留，否则设为今天（标注「首次记录」，不冒充发布日期）。
   - `bestRank[cat]`：取历史与今天 rank 的最小值；记录日期。
2. 拉 7 天前快照（缺失则 6–8 天窗口），计算每行 `delta7d = 7日前名次 - 当前名次`。
3. 30 日：拉 30 天前快照；没有时字段留空，UI 显示「30 日趋势积累中」。
4. 输出 `dist/history.json`，workflow 与 `rankings.json` 一起推 data 分支。
5. 校验：`history.json` 模型数 ≥ 500，否则拒绝覆盖（防止空历史）。

**行字段新增**：`delta7d`、`delta30d`、`firstSeen`、`bestRank`（当前类目）、`bestRankDate`。保留现有 `delta`（1 日）。

### 3.2 趋势 UI

**新页面 `pages/trends/trends`**（二级页，非 tab）：
- 标题「本周上升榜 · 近 7 日」
- 切换：上升 / 下降 / 新上榜
- 列表：名次、模型名、厂商、↑N / ↓N、当前综合排名、价格
- 底部「生成本周上升海报」：复用榜单海报版式，标题「本周上升 TOP10」，结论「本周上升最快：X（↑N）」，二维码指向 trends 页
- 数据来源与 7 日窗口说明；30 日未积累时提示

**首页入口**：快捷栏下方新增一行「📈 本周上升榜：X ↑N →」，点击进 trends。

**详情页趋势卡**（放 quick-card 之后）：
- 当前类目：近 1 日 ↑N · 近 7 日 ↑N · 近 30 日「积累中」
- 首次记录日期、历史最高名次
- 数据缺失时显示「趋势数据积累中」，不显示假 0

### 3.3 价格口径（诚实优先）

- 数据行增加 `priceUnit`：
  - 文本/视觉理解等 → `token`（展示 `/M tokens`）
  - 文生图/图片编辑 → `image`（展示「按张」；仅在价格来源明确为按张时）
  - 文生视频/图生视频 → `video`（展示「按秒」；仅明确来源时）
  - 无法确定 → `unknown`，展示「计价见来源」，不强行 `/M`
- 无价时统一文案：「暂无公开 API 定价（图像/视频多按张或按秒计价）」。
- 详情 quick card 保留来源/asOf；榜单价格与 OpenRouter 参考价不一致时继续单列。
- 本版不新增虚构价格；能补的只补 OpenRouter/官方已有数据（当前约 7 个图像模型）。

### 3.4 预算选型器

**新页面 `pages/planner/planner`**（二级页）：
- 输入：
  - 场景：日常聊天 / 编程 / 写作 / Agent / 数据处理（复用计算器预设）
  - 月预算：¥50 / ¥100 / ¥300 / ¥1000 / 自定义
  - 偏好：能力优先 / 性价比优先
- 算法（只使用有价文本模型）：
  1. 用场景的输入/输出万 tokens 估算月成本（与计算器同口径，`/100`，汇率取 `exchangeRate`）。
  2. 过滤成本 ≤ 预算；若为空，取最便宜的 3 个并提示「最低预算约 ¥X」。
  3. 能力优先：按主类目（编程场景取 text.coding，其他取 text.overall）排名百分位升序；性价比优先：按 `(百分位) / 价格` 综合排序。
  4. 输出 3 个推荐：模型名、月成本、排名百分位、价格、上下文、档案优势标签、推荐理由一句话。
- 操作：查看详情、加入对比、生成「选型卡」海报（复用榜单海报版式，标题「¥X/月 · 编程推荐」）。
- 入口：首页快捷栏下方「🎯 按预算选模型 →」；计算器页顶部增加入口。

## 9. 方案评审修订（2026-11-24，权威版本）

独立评审确认了 8 个问题，以下修订**覆盖前文**：

### 9.1 趋势口径：common-set（必须）

直接用原始 rank 差会被「新模型插入导致整体顺延」污染：11-17→11-24 的 text/overall，421 个共同模型里 413 个“下降”，上升榜只能填 3 行。

改为：
- 对每个 cat/dim，取「当前与锚点都在榜」的交集，**在交集内重新排名**，再算 `delta7d = 锚点交集名次 - 当前交集名次`。
- 新模型 `delta7d = null`，归入「新上榜」；锚点有、今天无 → 「掉榜」。
- 趋势页固定用 `text/overall`，不聚合 12 个类目；榜单只取当前 top100 且 `|Δ|≥2`。
- 展示实际窗口日期（如 11-17 → 11-24）；同一 baseName 的 (High)/(Max) 只取最高者。
- 1 日 `delta` 也改用 common-set 口径，避免同页两个口径。
- 用 fixture 断言：11-17→11-24 text/overall 交集 421、上升 44、下降 56；top100 内上升 16、下降 18。

### 9.2 快照校验

历史里有坏快照：11-18 只有 text+agent，10 个类目为空；11-17 是抓取失败后回退发布的旧文件。只检查 tag 存在不够。

- 每个快照记录 per-category 行数、唯一名数、sourceLastUpdated。
- 选锚点要求：每个类目行数在 7 日中位数的 ±10–20%，且名字 churn ≤5%；否则跳过，回退到窗口内最近的完整快照。
- 输出实际 `delta7dFrom` / `delta7dDays`。
- 30 日锚点用 28–32 天窗口（目前数据不足，暂不展示）。

### 9.3 tag 不可变 + CI 用 git 读快照

- 不再 `git tag -f` / `push -f`：每天首次创建 `vYYYY-MM-DD`，同日重跑创建 `vYYYY-MM-DD-N`。
- CI 读历史快照用 `git fetch --depth 1 origin tag vDATE && git show vDATE:rankings.json`，不从 jsDelivr 读；校验 blob SHA/size。
- 云函数按 `vDATE-N`（N 从大到小）→ `vDATE` 顺序尝试，兼容同日重跑。
- health_check 增加 tag 内容 size/SHA 校验。

### 9.4 history 初始化与保护

- 首次无 history：用当前数据 + 最老有效锚点初始化；不因「≥500」拒绝创建。
- 有 history：新输出必须是旧历史的超集，firstSeen 不能变晚、bestRank 不能变差；否则保留旧文件并告警。
- 历史读取失败（404/截断/网络）绝不当作空历史；本次跳过趋势更新。

### 9.5 选型器并入「推荐」tab

不新增独立 planner 页，避免第三个推荐入口：
- 保留「推荐」tab 和 `/pages/recommend`，顶部增加「场景 + 月预算 + 用量档（轻/中/重/自定义）+ 能力/性价比」。
- 抽 `utils/scenes.js`，计算器/推荐共用场景与用量定义。
- 结果卡与海报显著标注「按每月 X 万输入 + Y 万输出估算」。
- 预算不足时显示最低月费，不硬凑 3 个长尾模型。

### 9.6 性价比公式

`value = 质量分 / 月成本`（质量分 = 类目内百分位，top=1），并先限制在能力前 50%；或两段式：能力 top-K 内选最便宜。禁止用「百分位/价格」直接排序。
验收：同一预算下「能力优先」与「性价比优先」结果必须不同；性价比推荐成本不得高于能力优先最高成本。

### 9.7 用量档

固定 200万/200万 token 会误导。提供：
- 轻度：50万输入 / 50万输出
- 中度：200万 / 200万
- 重度：500万 / 500万
- 自定义
计算器/推荐/海报共用；结果与海报写清假设。

### 9.8 搜一搜：内容接入不可用，改物理页（P0）

不写公众号，靠自然搜索到 500 UV 的主路径：
- 新增云函数 `searchSubmit`，每日调用官方 `search.submitPages`（云调用权限 `search.submitPages`）。
- 提交页面：Top 100 模型详情（`pages/detail/detail` + `query=name=...`）、3 个榜单页、趋势页、推荐页。
- 每条带 `title`/`abstract`/`mainbody`/`time_publish`/`content_id`；正文来自档案与榜单事实。
- 需要后台开启搜一搜/爬虫开关；否则返回 85091。
- 分享路径加 `from=...`，记录来源，验证搜索/分享效果。
- 官方准入：非个人主体、月均 DAU≥5000、图文资讯主营、限定类目 → 本项目不符合，`submitPages` 暂停。
- 改为**物理落地页**：Top 20 模型 + 8 个系列 + 5 个场景，固定路径、独立标题/正文/内链；保持「页面收录」开启，靠爬虫自然发现。
- 现实预期：6–12 周甚至更久；500 UV 不是可控目标，分享（朋友圈/群，非公众号）可加速。

### 9.9 30 日趋势

暂缓：目前只有 9 天 tag，30 日锚点不足；字段预留、UI 显示「积累中」。

## 10. 纯搜索版实现记录（2026-11-24，实际发布范围）

内容接入准入不满足（个人主体/DAU/内容类目），submitPages 暂停；本版聚焦**纯自然搜索**：

### 已实现
- **20 个模型固定页**：`pages/model-<slug>/model-<slug>`，标题「模型名 排名与价格」，正文含厂商/排名/价格/上下文/规格/同系列/内链
- **8 个系列固定页**：`pages/family-<slug>/family-<slug>`，系列成员、排名、价格、互链
- **预算选型页**：`pages/budget/budget`，场景 × 月预算 → 3 个推荐；只统计有价文本模型，按万 token 估算，支持能力/性价比
- **内链**：首页「热门模型/系列/场景」、详情页「查看系列页」、推荐页「按预算选模型」
- **生成器**：`pipeline/generate_landing_pages.py` + `pipeline/landing-pages.json`，新增页面只需改 JSON 再生成
- **文档**：`docs/ops/search.md` 记录准入结论与页面收录 SOP

### 暂缓
- 7/30 日趋势与「本周上升榜」：评审发现原始名次差被新模型插入污染，且历史 tag 有坏快照/缓存问题；需要先做 common-set + 快照校验 + tag 不可变，工作量大，本版不上线。
- 30 日趋势：数据积累不足。
- Top 150/公司页：v1.6。

### 预期
- 纯搜索 39 → 500：3–6 个月，取决于收录；没有主动推送能力。
- 需要用户在后台保持「页面内容接入 → 基础设置 → 页面收录」开启。
