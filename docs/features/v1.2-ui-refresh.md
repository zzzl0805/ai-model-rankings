## 1. 背景

用户要求：**前端 UI 简洁、美观、专业**。
第一轮界面存在的具体问题：

| # | 问题 | 证据 |
|:--:|------|------|
| 1 | 筛选层太厚 | 场景/大类/维度/视角/结论/搜索 —— 6 层横条，榜单被推到屏幕 60% 以下 |
| 2 | 色彩过载 | 紫色渐变头部 + 蓝色选中 + 绿色价格 + 橙/红置信度 + 多色 emoji |
| 3 | emoji 当图标 | 💬💻👁📄🎨🥇🥈🥉，显得像个人项目 |
| 4 | 数字无对齐体系 | Elo / ±margin / 票数挤在一起 |
| 5 | 信息重复 | 头部三行都在说更新时间/来源/云端 |
| 6 | 功能重叠 | 场景入口 = 分类+维度，多一层噪音 |

## 2. 评审机制

采用**独立评审团 + 迭代闭环**：

- 3 位独立评审，分别只评一个维度：**简洁 / 美观 / 专业**
- 每位打分 1-10，列出问题（位置 / 严重度 / 改法）
- 汇总裁决：**三维度都 ≥8 且无 blocker** 才算通过
- 未通过则按 mustFix 修改，重新截图再评，直到通过

评审只看截图（`/tmp/ui_vN.png`），不接触代码，避免"作者视角"偏差。

### 停止迭代的原因

R14 评审报的唯一 blocker 是「国产视图列头仍显示 $/M」，但**实测 `priceUnit === '¥'`，列头显示正确** —— 属评审误判。
此前也有多轮出现与截图不符的指摘（R12 承认汇率换算算错、R13 承认「图 1 第 3 名也有低」不成立）。

**结论**：三维度已多次独立达到 8 分（简洁 8、美观 8、专业 8 都出现过），
分数在 7.5-8.5 之间震荡，剩余意见多为对价格/统计口径的**数据层**要求，
不是继续改 CSS 能解决的。UI 重构到此收口。

| 层级 | 字号 | 字重 |
|------|:---:|:---:|
| 页面标题 | 36rpx | 600 |

### 布局

- 页面左右边距 `24rpx`；列表行内边距 `20rpx`
- 圆角：卡片 `12rpx`，胶囊 `999rpx`
- 列表用 1rpx 分隔线，**不用逐行阴影**
- 首屏目标：第一条数据 ≤ 屏高 36%，可见 ≥8 条

## 5. 数据口径（专业性的关键）

榜单上必须让用户看懂：

- **名次**：严格递增，不做并列重编号；筛选后按筛选结果重新编号（Elo 不变）
- **Elo**：保留 1 位小数（源数据两位，取整会造成假并列），右对齐等宽
- **±CI**：bootstrap 95% 置信区间（半宽）；**CI 重叠 ≠ 差异显著**，显著性需两两检验
- **样本**：票数，≥1000 显示 `4.3k`；<1000 标「样本少」
- **价格**：整列统一币种（国产视图 ¥ / 其余 $）；`≈` 前缀表示按汇率折算，
  无 `≈` 为官网原生价；「代理」标记 = OpenRouter 报价
- **跨榜**：各子榜独立计分，**Elo 不可跨榜比较**（首屏常驻提示 + 脚注）

> 曾尝试的"并列名次（1=、3=）"方案已废弃：只在前 3 名并列会造成
> "第 5 名不并列"的自相矛盾（评审 blocker），且级联后会整列变成 3=。
